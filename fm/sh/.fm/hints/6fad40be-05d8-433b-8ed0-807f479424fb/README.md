# 관측 뷰 수 × SH 차수 실험 — 두 가지 실패 양상

> **Q.** 관측 뷰 수와 SH 차수를 바꾸며 전 구면 MSE를 측정한 실험에서 드러나는 두 가지 실패 양상은?
>
> **A.** 관측 수가 적으면 고차가 **과적합**해 관측 사이에서 색이 요동친다. 차수가 낮으면 하이라이트를 **표현하지 못한다**. 즉 관측 수와 차수 사이에 균형이 필요하다.

---

## 1. 실험이 무엇을 하는가 (`sh_walkthrough.py` §4.2)

3DGS는 SH 계수를 적분 $c_k=\int f\,Y_k\,d\Omega$ 로 구하지 않는다 — 진짜 $f$ 를 모르기 때문이다. 대신 **몇 대의 카메라에서 관측한 색**만 보고 계수를 거꾸로 맞춘다("관측으로부터의 역평가"). 노트북은 이 상황을 Gaussian 하나로 축소해 재현한다.

| 요소 | 노트북 구현 |
|---|---|
| 정답 함수 $f^\star(\mathbf d)$ | 확산 기본색 $(0.6,0.35,0.2)$ + 방향 $\mathbf h$ 쪽의 넓은 광택 로브 $0.6\,\max(0,\mathbf d\!\cdot\!\mathbf h)^8$ |
| 관측 | 구면에서 무작위로 뽑은 $n_{\text{view}}\in\{8,20,60,300\}$ 개 방향에서의 $f^\star$ 값 (잡음 없음) |
| 맞추기 | 차수 $L\in\{0,1,2,3\}$, 즉 $K=(L+1)^2\in\{1,4,9,16\}$ 개 계수를 **최소제곱** `torch.linalg.lstsq`로 결정 |
| 평가 | 관측한 방향이 아니라 **구면 전체** 128×256 격자에서 정답과의 가중 MSE |

핵심은 마지막 줄이다. 관측점에서의 오차(훈련 오차)가 아니라 **관측하지 않은 방향까지 포함한 오차**(일반화 오차)를 재기 때문에, "관측 사이에서 요동치는" 실패가 수치로 드러난다.

한 번 실행한 결과 (seed 고정이 없어 실행마다 조금씩 다르다):

```
전 구면 MSE (행: 관측 뷰 수, 열: 차수)
        L=0      L=1      L=2      L=3
n=   8  0.03077  0.02834  0.16546  0.37025
n=  20  0.03151  0.03058  0.02990  0.02972
n=  60  0.02844  0.02087  0.01270  0.00679
n= 300  0.02852  0.02044  0.01162  0.00519
```

## 2. 표를 읽는 법

- **행 = 관측 수 $n$** (아래로 갈수록 정보가 많음), **열 = 차수 $L$** (오른쪽으로 갈수록 모델이 유연함).
- **맨 왼쪽 열(L=0)**: 어느 행이든 ≈ 0.028~0.031. 관측을 300개로 늘려도 내려가지 않는다 → 데이터 부족이 아니라 **모델의 한계**다. 이것이 실패 양상 ①.
- **맨 위 행(n=8)**: 차수를 올릴수록 오히려 나빠진다 (0.028 → 0.165 → 0.370). 관측이 8개인데 미지수가 9개·16개다. 이것이 실패 양상 ②.
- **맨 아래 행(n=300)**: 차수를 올릴수록 단조 감소 (0.0285 → 0.0052). 정보가 충분하면 유연한 모델이 그대로 이득이 된다.
- **대각선**: 왼쪽 위(단순 모델·적은 데이터)에서 오른쪽 아래(유연한 모델·많은 데이터)로 내려가는 대각 방향이 "균형"이다. 오른쪽 위 삼각형은 과적합, 왼쪽 아래 삼각형은 과소적합(정보를 남겨두고 못 쓰는 상태).
- **n=20 행**은 경계 사례다. 미지수 16 < 관측 20이라 해는 유일하지만 여유가 거의 없어, 실행에 따라 L=3이 L=2보다 좋기도 나쁘기도 하다(아래 §4).

## 3. 편향–분산 트레이드오프의 교과서적 사례

통계학습에서 예측 오차는 대략 **편향² + 분산 (+ 잡음)** 으로 나뉜다.

| | 저차 (L=0, 1) | 고차 (L=3) + 적은 관측 |
|---|---|---|
| 무엇이 큰가 | **편향**(bias) | **분산**(variance) |
| 이유 | 상수(L=0)나 1차 코사인 로브(L=1)로는 $\cos^8$ 모양의 하이라이트 봉우리를 그릴 자유도가 없음 | 16개 계수가 8~20개 점에 맞추느라 관측 사이를 마음대로 휘어 다님 |
| 이름 | 과소적합(underfitting) | 과적합(overfitting) |
| 데이터를 늘리면? | 거의 나아지지 않음 (L=0 열이 평평) | 급격히 나아짐 (L=3 열이 0.37 → 0.005) |
| 3DGS에서 증상 | 광택·하이라이트가 사라지고 평균색으로 뭉개짐 | 카메라를 조금 돌리면 Gaussian 색이 번쩍이며 바뀜, 학습 시점 밖에서 색 깨짐 |

같은 실험을 §1.3에서 다른 각도로 이미 봤다: 진짜 $f$ 를 알고 적분으로 사영하면 L=3에서도 태양 봉우리가 흐릿하게 퍼진다. 그것은 **편향만** 있는 상황(관측 무한대)이고, §4.2는 여기에 **분산**이 더해진 상황이다.

## 4. 자유도 관점 — 미지수 $K$ 대 방정식 $n$

최소제곱은 선형 연립방정식 $A\,\mathbf c \approx \mathbf f$ 를 푼다. $A$ 는 $n\times K$ 행렬, $A_{jk}=Y_k(\mathbf d_j)$.

- **$n<K$** (n=8, L=2·3): 방정식보다 미지수가 많다. 관측점을 정확히 지나는 해가 **무한히 많고**, `lstsq`는 그중 **최소 노름 해**(계수 벡터의 길이가 가장 짧은 것)를 돌려준다. 이 해는 관측점에서는 오차 0이지만 관측하지 않은 방향의 값은 정답과 아무 관계가 없다. $A$ 의 rank가 8밖에 안 되어(측정: `rank=8`), 16차원 계수 공간 중 8차원은 데이터가 전혀 결정해 주지 않는다.
- **$n\approx K$** (n=16~20, L=3): 해는 유일하지만 $A$ 가 **거의 특이**하다. 조건수를 재 보면 n=16에서 약 **360**, n=20에서 약 17, n=60에서 3.8, n=300에서 1.5다. 조건수가 크면 관측값의 작은 차이(여기서는 어떤 방향을 뽑았느냐)가 계수에 수백 배 증폭된다. 실제로 n=16, seed를 바꿔 세 번 돌리면 L=3 MSE가 **9.7, 0.15, 1.55**로 널뛰기한다 — 이것이 "분산"의 문자 그대로의 의미다.
- **$n\gg K$** (n=60, 300): 과잉 결정. 최소제곱은 모든 관측을 평균적으로 만족시키는 해를 주고, 방향 샘플이 구면을 고르게 덮으므로 $A^\top A \approx \frac{n}{4\pi} I$ 에 가까워져(SH의 정규직교성) 해가 진짜 사영 계수 $\int fY_k$ 로 수렴한다. seed를 바꿔도 소수점 셋째 자리까지 같다.

즉 "관측 8개로 16계수를 맞춘다"는 것은 3점을 지나는 9차 다항식을 찾는 것과 정확히 같은 종류의 문제다.

## 5. 관측 수만이 아니라 **관측 방향의 분포**도 중요하다

노트북은 방향을 구면 전체에서 무작위로 뽑지만, 실제 3DGS 카메라는 대개 물체의 **한쪽**만 찍는다. 관측을 $z>0$ 반구로 제한하고 300개를 써서 L=3을 맞춰 보면:

```
앞면(관측 반구) MSE  0.0014     뒷면(미관측 반구) MSE  0.665
뒷면 복원 색 범위  [0.13, 2.49]   (정답 범위 [0.20, 1.20])
```

관측한 쪽은 완벽에 가깝지만, 뒷면은 정답보다 두 배 이상 밝은 값까지 나온다. 300개나 있어도 뒷면 기준으로는 **$n=0$** 이기 때문이다. 16개 SH 기저는 구면 전체에 걸쳐 정의된 다항식이므로, 앞면을 잘 맞추기 위해 조정한 고차 계수가 뒷면에서는 아무 제약 없이 외삽된다.

3DGS로 물체를 한쪽에서만 촬영하고 반대편으로 카메라를 돌리면 Gaussian 색이 형광색이나 검정으로 튀는 현상이 정확히 이것이다. 데이터로 결정되지 않은 방향의 색은 최적화가 "아무 값"으로 놔둔 것이다. (`clamp_min(0)`이 음수는 잘라 주지만 과대한 양수는 막지 못한다.)

## 6. 3DGS가 취하는 완화책

노트북 §4.2 "방법 B"와 원 논문 구현에 들어 있는 장치들이 모두 이 트레이드오프를 겨냥한다.

| 장치 | 내용 | 효과 |
|---|---|---|
| **고차 학습률 1/20** | `sh0` lr 2.5e-3, `shN`(15개 고차) lr 2.5e-3/20 (노트북에서는 2.5e-2와 그 1/20) | 고차 계수가 크게 움직이기 어렵게 해 암묵적 정규화(최소 노름 방향으로의 편향). 데이터가 요구하지 않는 고차 성분은 0 근처에 머문다 |
| **차수 램프업** | `sh_degree_interval`=1000 스텝마다 활성 차수 +1 (0→1→2→3). 노트북은 500스텝 간격으로 흉내 | 먼저 DC와 저차로 큰 구조(기본색, 완만한 명암)를 잡고, 그 위에 고차를 잔차 보정으로만 얹음. 초기의 거친 geometry 위에서 고차가 잡음을 흡수하는 것을 막는다 |
| **3차(16개)에서 멈춤** | 4차 이상을 쓰지 않음 | 차수를 올려도 분산·메모리(계수 48 → 75개)만 늘고, 날카로운 반사는 어차피 SH로 못 그림(§1.3) |
| **실제로는 수백 장 사진** | 일반적 데이터셋은 100~300장, 각 Gaussian은 그중 상당수의 뷰에서 보임 | 표의 아래쪽 행(n≫K)에 머물게 함. 뷰가 적은 캡처에서 SH 차수를 낮추는(`sh_degree=1,2`) 것이 흔한 실무 대처다 |
| **L1 + D-SSIM 손실, 렌더 픽셀 단위** | 계수는 픽셀 오차를 통해 간접적으로만 갱신 | 한 Gaussian의 색이 여러 픽셀·여러 뷰에 걸쳐 평균되어 개별 관측 잡음이 완화됨 |

방법 B 결과(n=60, Adam, 차수 램프업 포함)가 최소제곱 L=3과 비슷한 전 구면 MSE를 내는 것은, 이런 장치들이 있으면 경사하강도 안정적으로 "균형 잡힌" 해에 도달한다는 것을 보여준다.

## 7. 한 줄 요약

전 구면 MSE 표는 **왼쪽 열(저차)이 관측을 늘려도 내려가지 않는 편향의 벽**과 **위쪽 행(적은 관측)이 차수를 올릴수록 폭발하는 분산의 벽**을 동시에 보여준다. 16개 미지수를 결정하려면 그보다 충분히 많고 **구면을 고르게 덮는** 관측이 필요하며, 3DGS는 고차 lr 감쇠·차수 램프업·수백 장의 입력으로 이 균형을 맞춘다.
